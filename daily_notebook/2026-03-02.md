## Validation loss now uses data MSE only

**Files changed:** `src/training.py:130`

**Problem:** Validation (and therefore early stopping / best checkpoint selection) included physics residuals in `total_loss`.

**Root cause:** `run_epoch` passed `loss_fn=loss_fn` to `compute_loss_with_physics`. With `step=None`, `_ramp_factor` returns 1.0 so physics weights were always at full target level during validation, inflating `best_val_loss` with physics noise.

**Fix:** Changed to `loss_fn=None` so validation always uses pure MSE fallback.

**Impact:** Checkpoint selection and early stopping now track data accuracy only, independent of physics term magnitudes.

## Continuity loss formula corrected: was computing vorticity, not divergence

**Files changed:** `src/physics_loss.py:166-167`

**Problem:** Physics loss did not improve (and consistently degraded) model accuracy.

**Root cause:** `conservative_divergence` used face normal `(nx, ny) = (dy/length, −dx/length)` — perpendicular to the edge vector. On a vertex-centered radius-graph this computes `∂u_x/∂y − ∂u_y/∂x = −ω_z` (negative vorticity), NOT `∇·u = ∂u_x/∂x + ∂u_y/∂y`. Verified analytically: for `u=(x,0)` with `∇·u=1`, the old formula gives 0; the new formula gives 1.

**Fix:** Changed normal to along-edge direction: `nx = dx/length`, `ny = dy/length`. Flux becomes `u_face·(dx, dy)` — the normal component in vertex-centered FVM.

**Impact:** Continuity loss now measures actual velocity divergence. Expected to make the physics constraint meaningful and potentially improve accuracy when combined with data loss.
