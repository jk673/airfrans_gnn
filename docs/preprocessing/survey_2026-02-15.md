# AirfRANS Preprocessing Competitiveness Survey (2026-02-15)

## Scope
- Reviewed files:
  - `preprocessing/downsample_airfrans.py`
  - `preprocessing/edges_from_downsampled.py`
  - `preprocessing/config.py`
  - `src/preprocess_airfrans_edges.py`
- Goal:
  - Evaluate whether current preprocessing is clearly superior versus strong research/codebase practices.

## Executive Verdict
- Current preprocessing is a practical baseline.
- It is **not yet clearly superior** versus strong competitive pipelines.
- Biggest blocker: edge quality guarantees (degree floor / isolated nodes) are not reliably achieved in practice.

## Key Findings

### 1) Degree guarantee logic likely over-counts degree (High)
- Evidence:
  - `src/preprocess_airfrans_edges.py:109`
  - `src/preprocess_airfrans_edges.py:232`
  - `src/preprocess_airfrans_edges.py:351`
- Degree is computed as `bincount(row) + bincount(col)` while edges are already made bidirectional (`edge_all` includes both directions).
- This can inflate degree by ~2x, making `min_degree=2` behave closer to one-neighbor connectivity in undirected sense.

### 2) Isolated / low-degree nodes remain substantial (High)
- Evidence:
  - Repair and pruning flow: `src/preprocess_airfrans_edges.py:320`, `src/preprocess_airfrans_edges.py:357`, `src/preprocess_airfrans_edges.py:390`
- Quick empirical check (scarce train, first 10 graphs, default config):
  - Average isolated nodes (in-degree 0): `488.5`
  - Average nodes with in-degree < 2: `2578.9`
- This is risky for physics loss stability and neighbor-based operators.

### 3) `orig_index` robustness issue with non-trivial subsets (Medium)
- Evidence:
  - `preprocessing/downsample_airfrans.py:168`
- `orig_index` is saved using loop index `i`, not necessarily original dataset index for arbitrary subset/sampling cases.
- Current common use (front-slice limit) is okay, but shuffled/custom subsets can break alignment guarantees.

### 4) Voxel representative policy is simple first-hit (Medium)
- Evidence:
  - `preprocessing/downsample_airfrans.py:62` to `preprocessing/downsample_airfrans.py:66`
- This is fast and stable, but it does not optimize for curvature, flow gradient, uncertainty, or boundary-layer importance.

### 5) Surface preservation is a clear strength (Positive)
- Evidence:
  - `preprocessing/downsample_airfrans.py:47` to `preprocessing/downsample_airfrans.py:76`
- Spot check (10 samples): surface node count preserved 100% pre/post downsample.

## Quick Validation Snapshot (Local)
- Dataset: `AirfRANS scarce train` first 10 samples.
- Downsample target: default (`15k` to `30k` nodes).
- Edge defaults:
  - `global_radius=0.02`
  - `surface_radius=0.01`
  - `min_degree=2`
  - `knn_backup_k=4`
  - `knn_max_radius=0.05`

Observed:
- Graph size after downsample: ~15k to ~18k nodes in sampled cases.
- Surface nodes preserved.
- Degree path still leaves many isolated/low-degree nodes.

## Competitiveness Comparison (High-level)
- Current approach:
  - Fixed-radius graph + surface ring + heuristic degree repair.
  - Strong engineering practicality, easy reproducibility.
- Stronger competitive directions seen in recent work:
  - Adaptive meshing/remeshing or dynamic connectivity.
  - Multi-scale graph hierarchies with topology-aware refinement.
  - Pretraining or operator-learning regimes that reduce sensitivity to handcrafted connectivity.
  - Uncertainty-driven mesh refinement.

Conclusion:
- Competitive as a baseline.
- Not yet at a “clearly outstanding” preprocessing stack for research competitiveness.
